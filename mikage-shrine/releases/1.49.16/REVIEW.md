# 1.49.16 祭典记忆按场景与话题筛选

Entry 69原来只要有祭典旧记录，或阶段达到5，就把最多18条摘要整段送入每轮提示。祭典未筹备、地点为普通回廊时同样触发。本轮修投影条件和取材范围，存档中的记录完整保留。

## 本轮行为

| 情境 | 输出 |
| --- | --- |
| 普通回廊闲聊、休息；仅达到第五章或已有旧记录 | 该祭典条目输出为空。 |
| 最近玩家发言明确谈祭典，包含在普通回廊主动回顾 | 按所问类别和已提及的记录主体选择事实。 |
| 明确祭典/祭礼/屋台/万灯等地点，当前未暂缓话题或只求休息 | 按筹备、进行、事后回顾的实际状态取材。 |
| 明确表示别聊祭典、先搁下；或在祭典地点只想休息 | 本轮省略祭典事实。 |
| 多条相关记录 | 每轮最多3条；同类别/主体沿原最新记录优先。 |
| 指定人物的较早记录 | 在全部已核验摘要中匹配后再限3条，避免原18条窗口挡住点名旧事。重叠名称优先匹配更长主体，避免“新来客10”同时命中“新来客1”。 |

默认类别：筹备/构想采用构想、邀请、分工；实际举行采用到场、分工、片刻；已结束采用片刻、收场。玩家明确问邀请、分工、到场、回忆或收场时按所问类别取材，可在事后回看邀请原事实。类别选择不会把邀请改成答应、把答应改成到场。

最近发言只用于有限词语匹配，不执行、存储或回显其中指令。相关性与暂缓匹配不是自然语言语义分类器，未覆盖说法可能少读或多读；目标模型表现仍待实机观察。原条目末尾的事实/同意/到场/奖励与结算规则逐字保留，模型仍须按实际交流承接。

## 只读接口与缺失处理

本轮使用sillytavern-api-reference核对了固定上游：ST-Prompt-Template@ada54bb22e3dab0a07e473d383b4c2fe40bc6573的src/function/chat.ts与src/function/ejs.ts。前者的getChatMessage按角色筛选后选末条并返回经常规正则/宏处理的字符串，后者将该函数放入EJS共享上下文。核对的是模板接口，未借用Tavern Helper同名消息API。依据为GitHub连接器在该不可变修订的只读文件获取；通用网页获取不可用。

来源：
- https://github.com/zonde306/ST-Prompt-Template/blob/ada54bb22e3dab0a07e473d383b4c2fe40bc6573/src/function/chat.ts
- https://github.com/zonde306/ST-Prompt-Template/blob/ada54bb22e3dab0a07e473d383b4c2fe40bc6573/src/function/ejs.ts

目标酒馆安装版本未知，以上源码核对不是宿主通过。新读取为可选：typeof检查、try/catch与字符串类型检查均具备；缺失、异常、错误返回形态时仅按明确祭典地点筛选。此时普通回廊里只靠玩家提问的回顾无法触发，需要后续实机确认接口。这是明确的能力降级，没有改用宿主DOM或其他状态读取通道。

原getvar消息作用域与64楼有效存档回溯保持。本轮无变量写入、消息写入、额外模型调用、新字段、事件、存档迁移或记录删除；显示模式不读消息、不读状态、不输出。
