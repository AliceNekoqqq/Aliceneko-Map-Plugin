# 1.39.0 · R10 万灯花火祭

十项小游戏的逐项重做源实现齐备。本候选从1.38.0快照派生，第十项替换旧R10六灯换色处理器；前九项完整实现/CSS保留。真实SillyTavern、Android与作者玩法/审美验收仍pending，不标driver-accepted。沿用开发分支和草稿PR交付，不修改默认main。

## 可玩流程

1. 选暖金、樱粉或月白灯色，用巴卫的狐火点亮手边八盏新灯。每盏需累计0.65秒火力，可按住、亮起后划向下一盏；松手保留已积累的火力。也可键盘/点按选择小灯，再用“添一点狐火”分三次点亮。不同灯可以保留不同灯色；这八盏是可操作的新灯，不把背景画中的灯冒充为可操作千灯。
2. 八盏点好后入夜。使用已有R10夜景素材，不给白天图简单调暗；天空以Canvas承接升空轨迹和粒子，参道保留原预绘夜景。只改变本局的观赏时间，不改正式聊天时间。
3. 九拍分三段，光点依次从不同位置升起。等外圈收进亮环（0.72–1.16秒窗口）点击光点/下方同名按钮；成功绽开狐形、樱花或重环花火，连拍如实记录。早、晚都不扣资源，不会自动算命中；超出一圈后同一拍重新升起，未接的拍子不会跳过。
4. 支持流动跟拍、放慢拍速和逐拍观赏。逐拍模式每按一次推进0.2秒，上一束花火仍有余光时也不偷走下一拍的时间。可请巴卫提示当前拍，将光圈停在可接位置，仍由玩家确认；协助次数记入手帖。
5. 九拍结束可自选三种花火和三色，点夜空决定位置或用按钮放在中央；位置有边界限制。可问巴卫喜欢哪一束、请他再陪一会儿或安静看，随后自己收页或请他夹好。灯色和两人当前衣柜小人在夜景中保留。
6. 任一阶段可提前收步。只有实际点好八盏并命中九拍，才记录完整三段花火；部分点灯、未进入花火、部分拍数分别如实留帖，每局仅结算一次。

预绘素材沿用R10白天/黄昏/夜晚固定URL与共享衣柜。没有新图片/字体/库/远程脚本。点灯阶段用当前时景；进入花火才切换夜景；点灯阶段直接提前收步不会被写成已经入夜。图片404时隐藏破图并保留天空/地面底色及可操作控件；共享人物API缺失时文字显示“你/巴卫”。字体沿用现有字体与系统衬线回退。

花火渲染器是本项目原生Canvas源：先短轨迹升空，再由中心展开图案、拖尾与下落余光。每束60或72粒子，最多4束；DPR上限2；无闪屏、音频、WebGL或外部渲染库。减少动态效果时保留静态绽放图，默认逐拍；玩家仍可明确切换流动模式。Canvas仅作视觉，点灯/接拍/自选发射均有原生按钮替代。

实际阅读 https://fireworks.js.org/ 的官方说明页，参考升空轨迹、爆发和衰减的抽象表现；未运行该站控件，未引入该库或复制其代码/素材。视觉检查使用本项目实际构建模块375px手机与桌面截图。

## 生命周期与手机

只有按住未亮灯、流动拍子或尚未散尽的粒子才开帧循环。逐拍时只让余光动画推进，不推进拍子。没有持续空转的页面定时器。后台/失焦立即松开狐火、冻结时钟和粒子并清帧；回来手动继续。关闭清指针状态、帧循环、监听、ResizeObserver、衣柜订阅、图像回调与导出URL；由原弹窗壳回焦和恢复纵滚。

小灯点灯阶段52×68px，接拍按钮60px；夜景中的已点灯仅作静态展示。启动点灯/接拍时聚焦舞台内对应控件，便于手机保持主操作可见；控制区重建尽量保留原按钮焦点。320px、375px、1280px与320→568横向切换检查通过，无横向溢出。真实Android触控/大字体/低性能设备效果仍须实机验收。
